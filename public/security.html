Security & Data

For partners, insurers and procurement teams · Last updated: 7 October 2026

ScamGuard SOS is designed to collect as little as possible. There are no accounts and no passwords, and contacts never leave the phone. The only personal data our server holds is a live location, and only while the user is sharing it.

Logical architecture

How data moves between the user's phone, our server and other services.

Personal details never reach our server. The only personal data it receives is the live location during an SOS, which is deleted automatically.

2. Insurer assistance channel

  • For medical, accident, evacuation and claims situations, the app connects the user to their insurer's assistance team: by WhatsApp (with a pre-filled message) and/or by a one-tap call to the 24-hour assistance line.
  • The insurer comes from the partner's own link, or from the travel insurer the user chooses in the app. That choice is saved only on the user's phone.
  • For WhatsApp, the user sees the full message (name, policy number, country, location and live-map link) and presses Send themselves. ScamGuard does not see or keep it. Calls go straight from the user's phone.
  • The policy number is only included in messages to the insurer. It is never sent to personal SOS contacts or to ScamGuard's server.
  • Each partner gets its own link (e.g. scamguardsos.com/partner). The partner's name, WhatsApp number and assistance line are managed on the server, so changes take effect without an app update. The public version, without a partner link, shows no insurer options.
  • Partners receive anonymous usage totals for their link (opens, installs, SOS sent, chats opened), never individual users' data.

3. How the live map is protected

  • Each link uses a random, unguessable ID (16 random bytes).
  • Only the sender's phone holds the 24-byte key that can post locations. The server stores only a SHA-256 hash of that key.
  • Links stop working after 24 hours, or as soon as the user taps "I'm safe" or "Stop sharing".
  • Location is only read while the app is open. There is no background tracking.
  • Link creation is rate-limited per network address to prevent abuse. Map and API pages are excluded from search engines.

4. Security measures

  • HTTPS/TLS for all traffic, including the Android app.
  • Security headers: location access restricted to the app's own origin, MIME-sniffing blocked, and no referrer leaked to other sites.
  • No accounts or stored credentials, so there are none to steal.
  • No ads, no ad SDKs and no sale or rental of data.
  • Session recordings mask every personal field (names, phone numbers, messages, location and scam-checker text).
  • The Android app is a Trusted Web Activity, cryptographically linked to this domain through Digital Asset Links. It is signed by Google Play App Signing.
  • Source code is version-controlled on GitHub, and every change is traceable.

5. Hosting, uptime and continuity

  • Hosted on Railway in the Singapore region (asia-southeast1), with a managed PostgreSQL database in the same region.
  • Every release is health-checked before it receives traffic. If a new version fails, the previous version keeps running.
  • Core features keep working even if the server is unreachable: SOS SMS, emergency numbers and the scam checker run on the phone, and the app works offline once installed. Only the live map needs the server.
  • If the service stops: very little user data sits on the server, and live-map data expires on its own within days. For licensed partners, source-code escrow or a handover to partner-controlled hosting can be agreed in the contract.

6. PDPA (Singapore) alignment

  • Consent: location is only used after the user grants permission and starts an SOS, and every message is reviewed before sending.
  • Purpose limitation: data is used only to deliver alerts, show the live map and pick the correct country's emergency numbers.
  • Retention limitation: live-location data is deleted automatically (see section 1).
  • Access and deletion: requests are handled within 30 days through Delete your data.
  • Transparency: see the public Privacy Policy.
  • Partner arrangements: a Data Processing Agreement can be signed with each licensed partner.

7. Certifications and testing

ScamGuard SOS does not currently hold SOC 2 or ISO 27001 certification, and it has not yet had an independent penetration test. On request, we can commission an independent security test and complete a partner's vendor security questionnaire as part of onboarding.
